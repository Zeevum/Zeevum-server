# Zeevum-server
Сервер мессенджера Zeevum на Rust: TLS-шифрование, SQLite, авторизация по токену, друзья и приватные чаты

## Возможности проекта
- TLS (rustls, TLS 1.2/1.3): весь трафик зашифрован. Подходят сертификаты Let's Encrypt (`.pem`, `.crt` и `.crt.key`)
- Регистрация с Proof-of-Work и проверкой стойкости пароля
- Вход по логину и паролю, autologin (автоматический вход по токену), автоматическое продление сессии
- Друзья: поиск по логину, заявки, принятие
- Приватные чаты (пока что пользователь-пользователь, без групп и общих чатов)
- Статусы прочтения сообщений
- Защита от брутфорса. Блокировка IP после 5 неудачных авторизаций за 5 минут. Время ответа не зависит от существования логина
- Журналирование с ротацией по дням, настраиваемый уровень логирования
- Конфигурация через переменные окружения (Для исходников: .env / systemd EnvironmentFile)
- SQLite: WAL, внешние ключи, версионированные миграции

## Что планируется в будущем
- Доставка офлайн-сообщений при выходе в онлайн — сообщения, отправленные офлайн-пользователю, хранятся на сервере и видны ему при открытии чата
- Групповые чаты и медиа
- Сквозное шифрование: шифрование транспортное, сервер видит содержимое сообщений
- Несколько одновременных сессий: новый вход замещает предыдущее соединение
- Windows-сервис: для Windows доступен консольный exe (запуск в терминале)

## Требования
- Rust 1.85+ (edition 2024)
- Cargo
- TLS-сертификат и ключ в PEM (Let's Encrypt или mkcert для локальной разработки)

## Сборка и запуск (разработка)
```bash
git clone https://github.com/Zeevum/Zeevum-server.git
cd Zeevum-server
cp .env.example .env
cargo test
cargo run
```
Для локального TLS удобно использовать mkcert:
`mkcert -install && mkcert -cert-file certs/localhost.crt -key-file certs/localhost.crt.key localhost 127.0.0.1 ::1`

> Сервер не стартует без TLS_CERT_PATH и TLS_KEY_PATH

## Конфигурация
| Переменная | Описание | По умолчанию |
|---|---|---|
| `SERVER_ADDRESS` | Адрес и порт, на которых слушает сервер | `0.0.0.0:1990` |
| `LOG_LEVEL` | 	Trace, Debug, Info, Warn, Error | `Info` |
| `DB_PATH` | Путь к файлу БД | _Авто (Зависит от ОС)_ |
| `READ_TIMEOUT`	| Таймаут чтения сообщений после авторизации (сек) |	`300` |
| `HANDSHAKE_TIMEOUT`	| Таймаут TLS и Auth рукопожатия при подключении (сек)	| `10` |
| `SESSION_DURATION_HOURS` | Часы жизни сессии пользователя, продлевается при каждом входе	| `720` |
| `TLS_CERT_PATH` |	Путь к файлу сертификата (`.crt` / `.pem`) |	- (Обязателен) |
| `TLS_KEY_PATH`	| Путь к файлу приватного ключа (`.key`) |	- (Обязателен) |
| `POW_DIFFICULTY`	| weak / medium / strong |	`Medium` |

### Пример (см. также .env.example):

```env
SERVER_ADDRESS=0.0.0.0:1990
LOG_LEVEL=Info
DB_PATH=/var/lib/zeevum-server/database.sqlite
READ_TIMEOUT=300
HANDSHAKE_TIMEOUT=10
SESSION_DURATION_HOURS=720
TLS_CERT_PATH=/etc/letsencrypt/live/example.com/fullchain.pem
TLS_KEY_PATH=/etc/letsencrypt/live/example.com/privkey.pem
POW_DIFFICULTY=medium
```
> В production рекомендован явный DB_PATH.

## Деплой на Linux
Установщик из раздела Releases устанавливает сервер как systemd-сервис (***Требуются root права***):
```bash
wget https://github.com/Zeevum/Zeevum-server/releases/latest/download/zeevum-server-installer-linux-amd64.sh
chmod +x zeevum-server-installer-linux-amd64.sh
sudo bash zeevum-server-installer-linux-amd64.sh
```
Скрипт: Создаёт системного пользователя, спрашивает пути к сертификатам и параметры, выдаёт права на сертификаты через ACL, скачивает бинарник из релиза, создаёт пользователя в системе (не-root пользователь, NoNewPrivileges, ProtectSystem=strict,PrivateTmp)

Повторный запуск скрипта — это режим обновления: бэкап бинарника, загрузка новой версии, откат при неудачном старте новой версии

### Параметры установщика:
| Команда с параметрами | Описание |
|---|---|
| `sudo bash zeevum-server-installer-linux-amd64.sh --tag v0.2.0`                | Конкретная стабильная версия |
| `sudo bash zeevum-server-installer-linux-amd64.sh --pre-release v0.2.0-rc.1` | Конкретный pre-release |
| `sudo bash zeevum-server-installer-linux-amd64.sh --remove`                    | Удаление (с опцией сохранения данных) |

## Деплой на Windows
Консольная сборка доступна в релизах. Запускается из терминала, конфигурация подтягивается из переменных окружения или .env рядом с бинарником
> В будущем планируется установщик для Windows 10+

## Безопасность
1. Argon2id — пароли только в виде PHC-хэшей со случайной солью
2. zxcvbn — сервер отклоняет слабые пароли
3. Rate limiter — по IP: 5 неудач в окне = 5 минут отказ в подключениях (в будущем планируется переработка этого механизма)
4. PoW регистрации — SHA-256 с требованием ведущих нулевых бит: weak = 16, medium = 20, strong = 24. Это барьер от массовой автоматической регистрации
5. Протокол — построчный JSON, жёсткий лимит 64 КиБ на фрейм, проверка версии протокола в рукопожатии
6. Логи — не содержат учётных данных и содержимого сообщений (В дальнейшем планируется полная переработка логируемых данных)
