# Zeevum-server
Безопасный многопользовательский чат-сервер на Rust с управлением пользователями через SQLite и сквозным шифрованием TLS (Требуется сертификат)

## Возможности проекта
- Сквозное шифрование: Весь трафик между клиентом и сервером шифруется с помощью `rustls`. Поддерживаются сертификаты Let's Encrypt (`.crt` и `.crt.key`)
- Безопасная авторизация: Хэширование паролей с использованием `Argon2id`
- Политика паролей: Проверка сложности пароля на стороне сервера с помощью алгоритма `zxcvbn`. Слабые пароли отклоняются
- Защита от брутфорса: Блокировка IP-адреса после 5 неудачных попыток входа на 5 минут
- Время ответа при логине одинаково, независимо от того, существует ли пользователь в базе
- Продвинутое логирование: Асинхронный логгер с цветным выводом в консоль, записью в файлы и автоматической ротацией по дням
- Многопоточность: Выделенный поток для каждого клиента
- Команды: `/ping` (проверка связи), `/exit` (корректное завершение сессии)
- Конфигурация: Через переменные окружения (файл `.env` или systemd EnvironmentFile).
- База данных SQLite: Автоматическая миграция, режим WAL для повышения производительности.

## Требования
- Rust 1.85+
- Cargo
- OpenSSL (для генерации сертификатов, если не используются Let's Encrypt)

## Установка и запуск (Для разработки)
1. Клонируем репозиторий:
```bash
git clone https://github.com/Zeevum/Zeevum-server.git
cd Zeevum-server
```

2. Копируем пример конфигурации:

```
cp .env.example .env
```
> отредактируйте .env при необходимости

3. Сборка и запуск:
- Debug сборка:
  ```
  cargo run
  ```

- Релизная сборка:
  ```
  cargo build --release
  ```

> По умолчанию сервер слушает `0.0.0.0:1990`. Адрес можно изменить в `.env` через переменную `SERVER_ADDRESS`.

> Важно: Сервер не запустится, если не указаны TLS_CERT_PATH и TLS_KEY_PATH

## Деплой на Linux
Для автоматической установки сервера как systemd-сервиса используйте установочный скрипт.
1. Скачайте скрипт `zeevum-server-installer-linux-amd64.sh` на ваш сервер
    ```
    wget https://github.com/Zeevum/Zeevum-server/releases/latest/download/zeevum-server-installer-linux-amd64.sh
    ```
2. Запустите его от имени `root`:
    ```
    sudo bash zeevum-server-installer-linux-amd64.sh
    ```

Скрипт:
- Создаст системного пользователя `zeevum-server`.
- Запросит пути к сертификатам и другие настройки.
- Настроит права доступа (ACL) к сертификатам.
- Скачает последний релиз с GitHub.
- Создаст и запустит `systemd` сервис с жесткими ограничениями безопасности.

## Конфигурация (`.env`)
| Переменная | Описание | Значение по умолчанию |
|---|---|---|
| `SERVER_ADDRESS` | Адрес и порт, на которых слушает сервер | `0.0.0.0:1990` |
| `DB_PATH` | Путь к файлу БД | _Авто (Зависит от ОС)_ |
| `TLS_CERT_PATH` |	(Обязательно) Путь к файлу сертификата (`.crt` / `.pem`) |	- |
| `TLS_KEY_PATH`	| (Обязательно) Путь к файлу приватного ключа (`.key`) |	- |
| `READ_TIMEOUT`	| Таймаут чтения сообщений после авторизации (сек) |	300 |
| `HANDSHAKE_TIMEOUT`	| Таймаут TLS и Auth рукопожатия при подключении (сек)	| 10 |

> При использовании установщика, переменные HOME и XDG_DATA_HOME автоматически направляются в /var/lib/zeevum-server, чтобы логгер имел права на запись.

## Команды клиента
- `/ping` – получить от сервера ответ `PONG`
- `/exit` – корректно завершить соединение

Все остальные сообщения логируются на сервере

## Архитектура безопасности
- Argon2id: Пароли никогда не хранятся в открытом виде. Используются случайные соли и ресурсоемкое хэширование.
- zxcvbn: Сервер не доверяет клиенту и самостоятельно проверяет энтропию пароля. Оценка должна быть >= 2 (Fair).
- Rate Limiter: Хранит историю неудачных попыток в памяти (HashMap), защищая от перебора паролей.
- systemd Hardening: В production сервер работает от имени не привилегированного пользователя с ограничениями `ProtectSystem=strict` и `NoNewPrivileges=true`.
